# Running the study: the full operating sequence

This guide lists every step from connecting the API keys to the public report,
in order. Hebrew version: [below](#הוראות-הפעלה-בעברית-הרצף-המלא).

**Owner: your one-time setup is [OWNER_SETUP.md](OWNER_SETUP.md)** (seven
secrets and provider limits). **No step needs a local command line** (PR 17):
every dev step (steps 3 to 8) runs from the workflow **dev pipeline**, the SEC
dataset is generated by its free stage `sec-dataset-prepare`, every frozen test
run (step 10) runs from the workflow **frozen test run**, and the results of
every run are committed to the branch `results-log`, where the orchestrator
reads them through the GitHub API (it cannot download artifacts). Pinning the
SEC hash, the freeze and the publication of results are pull requests the
orchestrator opens. The `python -m ...` commands shown in the steps are what the
workflows run; they remain usable on a computer but are never required. The
single-config workflow **baseline** keeps working as described in the steps.

**Nothing here has been run against a live API yet.** The model clients, the web
search client and the page fetcher were tested against recorded-shape fixtures
only. The smoke runs (steps 3 and 7) exist to find out cheaply whether the live
services behave as coded. All costs below are dry-run estimates or budget caps
from the configs, not measurements; every cap is a PROPOSED value
(PREREGISTRATION.md section 17, items 13 and 43).

**Layer 2 since PR 17: SEC financial filings.** Layer 2 is a second
confirmatory layer (H1 and H2 per model, the layer-1 thresholds): questions
about a figure in a US public company's annual report (Form 10-K), answered from
the financial statements of that filing and/or of a same-industry peer's filing;
gold values are the filings' XBRL facts. The dataset is generated once, for
free, from SEC EDGAR (step 8). GRAB-RAG, layer 2 until PR 17, is kept under
`configs/extended/` and not run. The layer-2 estimates are conservative dry runs
on a synthetic stand-in; the free dry run on the real dev data replaces them
before the freeze.

What makes it fit: three low-cost primary models (`openai-low`, `google-low`,
`zai-low`) on every item with one repeat, at their lowest reasoning setting;
every gate arm reuses the answer `no_gate` already paid for; every dev run after
the baseline reuses the baseline's answers (seed runs, below); the mid-tier
models (`openai-mid`, `google-mid`, `zai-mid`), the
judges and the nondeterminism check run on fixed subsamples; web search uses
SerpApi's free plan. The full-scale design of earlier versions is kept, not
run, under `configs/extended/` ("if funding becomes available").

**Providers (PR 14).** The study uses only the providers the owner funds:
OpenAI (slots A, B and the decomposer), Google (E, F), Z.ai (H `glm-5.3-flash`,
I `glm-5.3`) and Moonshot (the judge J). Anthropic and DeepSeek are not used;
their configs exist only under `configs/extended/`. The GLM models cannot switch
their thinking off: they run at `reasoning_effort = "low"`, their lowest
setting, and their estimates assume 100 to 2,000 hidden tokens per call.

**If a cap stops a run.** A run whose model reaches its cap stops that model and
stays unfinished. It can be resumed only with the same config (a changed cap
changes the config). On dev: re-derive the cap from the reserve in a pull
request and start a new run that reuses the stopped run's answers (seed runs).
The test configs' caps are re-derived from the usage measured by the smoke run
and the dev baseline before the freeze, so that a test run is never stopped.

`confirm_spend` (every stage except the free `check-secrets` and
`sec-dataset-prepare` refuses without it). The
dialog values of every stage are in [OWNER_SETUP.md](OWNER_SETUP.md). The
configs of each stage are defined once in `binding_gate.pipeline.STAGES`

Seed runs are found without any input: `dev-rest` takes the workflow run of the
newest `dev-baseline--decision` and downloads its
`dev-baseline--dev_baseline--runs-*` artifacts into `seeds/`; `layer2-dev`
takes the `layer2-dev--dev_sec_baseline--runs-*` artifacts of its own workflow
run.

**Artifact names** (listed through
`GET /repos/{owner}/{repo}/actions/runs/{run_id}/artifacts`; the orchestrator
cannot download them and reads their non-sensitive content on the branch
`results-log`, below):
`<stage>--<config stem>--<kind>-<model label>`, plus `-attempt<N>` on a re-run
attempt. Kinds: `runs-<model>` (run directories), `baseline-report`,
`runs-encrypted-all-models` and `layer3-summary-all-models` (layer 3),
`snapshot-manifest-all-models`, `ledger`; and `dev-baseline--decision`,
`smoke--dev_smoke--usage-check`, `dev-rest--decomposer_eval_dev--decomposer-eval`,
`dev-rest--dev_llm_judge--rescore`, `dev-rest--analysis`, `check-secrets--report`,
`pipeline--<stage>--ledger`; PR 17: `sec-dataset-prepare--dataset`,
`layer2-dev--dev_sec_smoke--usage-check`, `layer2-dev--analysis`, and from the
frozen test run `frozen-test--<layer>--{ledger,access-log,runs-all-models,results,
layer3-summary-all-models,runs-encrypted-all-models}`. Started by hand, `baseline.yml` keeps its old names
(`runs-<model>`, `baseline-report`, ...; ledger: `ledger`).

**Budget ledger** (`python -m binding_gate.ledger`; composite action
`.github/actions/ledger-check`). Before every paid step (the whole stage in the
pipeline's plan job, then each config again; and the plan job of every paid
`baseline.yml` run) it:

0. (PR 17) reads every `ledger.json` kept on the branch `results-log`
   (`python -m binding_gate.results_log export-ledgers`): their entries are
   carried forward and the artifacts they cover need not exist any more;
1. lists every artifact of the repository through the REST API with the
   workflow's `GITHUB_TOKEN` (`actions: read`) and keeps those of runs started by
   hand (`workflow_dispatch`) in this repository;
2. downloads the run directories (`runs-*`), the decomposer measurement, the
   judge scores and the layer-3 summaries, and the earlier ledger results (whose
   entries are carried forward, so artifacts they already read are not
   downloaded again);
3. computes the ACTUAL spend: every logged call priced with
   `configs/prices.toml` exactly as the runner prices it (or the spend the
   runner recorded, if larger); one entry per run, so copies count once;
4. REFUSES the paid step when spend so far + the caps about to run exceed
   `hard_limit_usd` (50) of `configs/budget.toml`, when any spend is unknown
   (an encrypted run without its summary, an artifact that cannot be read, a
   call that cannot be priced, an EXPIRED spend artifact not covered by an
   earlier ledger or by `results/ledger.json`), or when another hand-started
   workflow run is in progress;
5. writes `ledger.json` and `ledger.md` to the job summary and to the artifact
   `...--ledger`.

Residual risk: artifacts are kept 90 days (`retention-days: 90` on every
upload, GitHub's maximum for public repositories; a lower repository setting
wins). Since PR 17 this no longer loses spend: after every run the results-log
workflow computes the ledger and commits it to the branch `results-log`
(`runs/<id>-<stage>/ledger-after-run/ledger.json`), and every later ledger reads
those snapshots. Spend that never reached an artifact (a job killed before its
upload step, a run on a computer) is invisible unless it is entered in
`results/ledger.json` as a `manual:<id>` entry
(`{"usd": ..., "kind": "manual", "source": "..."}`). The provider spending
limits stay the outer safety net. Offline, the same computation:
`python -m binding_gate.ledger compute runs/ seeds/ --json ledger.json`.

**Layer-3 summary.** A live-web run directory holds third-party page text and is
uploaded only encrypted. Before encryption, in the same job, `python -m
binding_gate.layer3_summary` writes `layer3_summary.json` (artifact
`...layer3-summary-all-models`): per run the cost (the ledger's entry), metrics,
searches and snapshot counts; per record the item, arm, model, outcome label,
the answer value cut to 100 characters, the quote only as SHA-256 and length,
the attempts with evidence ids, hashes and URLs, gate decisions with check
names, statuses and reason codes, and cost per call purpose; per page the URL,
time, status and hashes. Never page text, titles, snippets, queries, quotes,
prompts, raw outputs or error messages (the exact list is in the module
docstring and is tested).

**The results-log branch (PR 17;** `binding_gate.results_log`**,**
`.github/workflows/results_log.yml`**).** When a run of **dev pipeline**,
**baseline** (started by hand) or **frozen test run** has finished - dry or paid,
successful, failed or cancelled - the workflow **results log** (event
`workflow_run`; it holds no secret, so no job with an API key ever has a token
that can write to the repository) downloads that run's artifacts, keeps only the
report files on an allow-list, scans each of them, and commits them as the bot
`github-actions[bot]` to the branch `results-log` (an orphan branch, never
merged into `main`; pushes are retried with `git pull --rebase`):

- `runs/<workflow run id>-<stage>/run.json`: workflow, title, conclusion, commit,
  every kept file with its SHA-256, and every file left out with the reason;
- `runs/<workflow run id>-<stage>/<artifact name>/...`: the check-secrets report,
  the smoke usage checks, the stop-rule decision, ledger results, calibration
  reports, analyses (`analysis.json`, `report.md`, `index.json`, `*.log`),
  baseline reports, the decomposer report, the judge agreement, layer-3 summaries,
  run manifests and `invocations.jsonl`, the SEC `prepare.json`
  (`content_sha256`), `manifest.json` and `selection.json`, live-web publish
  manifests;
- `runs/<workflow run id>-<stage>/ledger-after-run/ledger.json`: the budget ledger
  right after the run;
- `frozen/<layer>/<workflow run id>/`: the published results of a frozen test run
  (step 10).

`<stage>` is the dev-pipeline stage, `baseline-<config stem>-<model>-<dry-run|paid>`
or `frozen-<layer>`; a re-run attempt N adds `-attempt<N>`. Never committed:
traces, dataset items, decomposer records, judge scores, live-web snapshots,
encrypted or archived files, figures, and any file that looks like it holds a
secret (API-key or token patterns, an e-mail address, the value of a secret) or
page text (a JSON string over 2,000 characters, a `text`/`content`/`quote`/
`messages` field over 300). The orchestrator reads a file with
`GET /repos/{owner}/{repo}/contents/runs/<id>-<stage>/<path>?ref=results-log`.

**Frozen test runs in GitHub Actions (PR 17;** `.github/workflows/frozen_test.yml`**,**
`binding_gate.frozen_ci`**).** Inputs `layer` (`layer1`, `layer1_midtier`,
`layer2_sec`, `layer3_live`), `tag` and `confirm_spend`; the dialog is in step 10
and in [OWNER_SETUP.md](OWNER_SETUP.md). The plan job refuses, before anything
is run or logged, an unchecked confirmation, a tag that is not
`prereg-freeze-<name>`, a tag that does not exist, and an earlier frozen run's
access-log branch that is not merged yet. The ledger checks the caps of the
layer's config at the tag. The run job checks out exactly the tag, puts
`main`'s `audit/test_access_log.jsonl` in the working tree (the lock ignores
changes to that one file, so the new entries chain onto `main`'s last entry),
gets the dataset, checks that nothing else is modified, and runs
`python -m binding_gate.cli frozen-test-run --config <layer config> --tag <tag>
--purpose "..." --confirm-spend`: the lock decides (clean tree, HEAD equal to the
tag, status FROZEN) and logs the access. All models of a layer run in ONE job and
ONE access, because PREREGISTRATION.md section 17 item 18 is still open; a
GitHub-hosted job ends after 6 hours, so the paid step stops after 330 minutes
and the run is then left unfinished (finishing it is a further logged access,
which needs an amendment). Afterwards the audit-log job checks that the new log
is `main`'s log plus entries of this tag only (hash chain intact), pushes it on
the branch `audit-log/frozen-<run id>` and opens a pull request into `main`
(merge it before the next frozen run; if the repository does not let Actions
open pull requests, the orchestrator opens it from the pushed branch). The
results-log job commits the published results (step 11's allow-list; layer-1
traces included, compressed when large; never layer-2 or layer-3 traces or page
text). Layer-3 page text stays only in the encrypted artifact.

Every step runs in GitHub Actions:

- **dev pipeline** (`.github/workflows/dev_pipeline.yml`): steps 3 to 8, one
  stage per dialog (above and in OWNER_SETUP.md);
- **baseline** (`.github/workflows/baseline.yml`): one config on the dev split
  (`python -m binding_gate.cli run` or its dry run) after the free preparation it
  needs (dataset, MiniCheck weights, seed runs); the dev pipeline calls it;
- **frozen test run** (`.github/workflows/frozen_test.yml`): step 10;
- **results log** (automatic): the reports of every run on the branch
  `results-log`.

The commands marked "CLI" in the steps are what these workflows run; on a
computer (section "Local setup") they give the same result, but no step
requires them.

## Where to click (every workflow step)

GitHub → repository → **Actions** → workflow **baseline** (left column) →
**Run workflow** (right side). Fill the dialog exactly as in the step's table,
then press the green **Run workflow** button. "checked" / "unchecked" refer to
the two boxes. The dialog shows these fields:

| Field in the dialog | Input name in the workflow |
|---|---|
| Use workflow from (Branch) | the branch |
| Run config (path in the repository) | `config` |
| Model label from the config, or "all" (one parallel job per model) | `model` |
| Dry run: count calls and estimate cost; no model API is called | `dry_run` |
| I confirm that paid API calls may be made (needed when dry run is unchecked) | `confirm_spend` |
| Seed runs: id of the earlier workflow run that holds them (empty unless the config names seed runs) | `seed_run_id` |

A paid run happens only with "Dry run" unchecked **and** the confirmation box
checked. Model labels: primary `openai-low`, `google-low`, `zai-low`; mid-tier
`openai-mid`, `google-mid`, `zai-mid` (only in the smoke run and the mid-tier
test run). `configs/dev_llm_judge_checks.toml`,
`configs/dev_live_smoke.toml` have
`openai-low` only; `configs/dev_live.toml` has `openai-low` and `google-low`.
With `all`, each model runs as its own parallel job, except live-web configs
(layer 3), which run as one job over every model whose API key is set.

Results of a workflow run are on the run's page under **Artifacts**:
`runs-<model label>` (manifest, traces, per-model baseline report) and
`baseline-report` (stop-rule outcome over all models of the run); for live-web
runs `runs-encrypted-all-models` (the run directory, encrypted) and
`snapshot-manifest-all-models` (URLs, times, hashes; no page text). To analyse
them locally, unzip each `runs-<model label>` artifact into `runs/`
(`unzip runs-openai-low.zip -d runs/`), or with the GitHub CLI:
`gh run download <workflow run id> -n runs-openai-low -D runs/`.

## 6. Dev runs that reuse the baseline's answers

### Seed runs (how the answers are reused)

`dev_gated.toml`, the five ablation configs, `dev_repeats.toml`,
`dev_baselines.toml` and `dev_llm_judge_checks.toml` contain
`seed_responses_from = ["seeds/*"]`. In the dialog, "Seed runs" =
**the number of the step-4 workflow run** (the number at the end of its URL).

runner takes every answer the baseline already received from its traces
instead of paying for it again; each reused answer is recorded in the new trace
with `cache_hit` and `seeded_from` and costs nothing. Only the other calls are
paid (decomposer, judge, `prompt_entity_check`, repeats 1-2 of
`dev_repeats.toml`; MiniCheck runs on the CPU for free). The dry run with the
same "Seed runs" value shows, per model, how many answer calls are seeded
(`SEEDED RESPONSES`) and leaves them out of its estimate. A paid run refuses if
no seed run was downloaded (so nothing is paid twice by mistake), and refuses a
seed that is not a dev run, that used another dataset pin, another model spec
for the same label (timeouts and retries aside) or another answer prompt, a
live-web run, or a seed trace modified after its run closed; a test run never
uses seeds. Locally: `gh run download <number> -n runs-openai-low -D seeds/`
(one per model label), then run the CLI as usual.

**אף שלב לא צריך שורת פקודה מקומית (PR 17):** שלבי ה-dev רצים מה-workflow **dev pipeline**, מאגר SEC נבנה בשלב החינמי `sec-dataset-prepare`, ריצות ה-test המוקפאות רצות מה-workflow **frozen test run**, והתוצאות של כל ריצה נכנסות ל-branch `results-log`, שממנו ה-orchestrator קורא אותן דרך ה-API של GitHub (הוא לא יכול להוריד artifacts). נעיצת ה-hash של SEC, ההקפאה ופרסום התוצאות הם pull requests שה-orchestrator פותח. פקודות ה-`python -m ...` בשלבים הן מה שה-workflows מריצים; אפשר להריץ אותן גם על מחשב, אבל אף שלב לא מחייב את זה.

**ה-ledger** (`python -m binding_gate.ledger`): לפני כל צעד בתשלום הוא מוריד דרך ה-API של GitHub את ה-artifacts של כל הריצות הקודמות שהופעלו ידנית, מחשב את ההוצאה **בפועל** (כל קריאה מתומחרת לפי `configs/prices.toml` בדיוק כמו ב-runner), ומסרב אם ההוצאה עד עכשיו ועוד התקרות שעומדות לרוץ עוברות 50 דולר, אם יש הוצאה לא ידועה (artifact שפג תוקפו ולא מכוסה ב-`results/ledger.json`, ריצה מוצפנת בלי סיכום), או אם ריצה ידנית אחרת עדיין פעילה. מאז PR 17 ה-ledger קורא גם את כל קבצי ה-`ledger.json` שב-branch `results-log`, ואחרי כל ריצה נכתב שם ledger חדש (`runs/<מספר>-<שלב>/ledger-after-run/ledger.json`), כך שהוצאה לא הולכת לאיבוד כש-artifacts פגים אחרי 90 יום. הוצאה שנעשתה מחוץ ל-GitHub Actions נרשמת ידנית ב-`results/ledger.json`.

**סיכום שכבה 3:** לפני ההצפנה, באותו job, נכתב `layer3_summary.json` לא מוצפן: עלויות, מדדים ותוצאה לכל שאלה, כתובות ו-hash — בלי טקסט של דפים ובלי ציטוטים. ה-ledger קורא ממנו את העלות.

**ה-branch ‏`results-log` (PR 17):** בסוף כל ריצה של **dev pipeline**, של **baseline** שהופעל ידנית ושל **frozen test run** (גם dry run, גם כישלון), ה-workflow **results log** (שאין לו אף secret, כך שאף job עם מפתח API לא מקבל הרשאת כתיבה לריפו) מוריד את ה-artifacts של הריצה, שומר רק קובצי דוח מרשימה סגורה, סורק כל קובץ, ועושה commit בשם `github-actions[bot]` ל-branch ‏`results-log` (branch יתום שלעולם לא מתמזג ל-main): `runs/<מספר הריצה>-<שלב>/` עם `run.json` (מה נשמר ומה הושאר בחוץ ולמה), הדוחות לפי שם ה-artifact, ו-`ledger-after-run/ledger.json`; ותוצאות ריצה מוקפאת ב-`frozen/<שכבה>/<מספר הריצה>/`. לעולם לא נכנסים לשם: traces, פריטי מאגר, ציוני שופט, snapshots של דפים, קבצים מוצפנים, וכל קובץ שנראה כמו secret (תבנית של מפתח, אימייל, ערך של secret) או טקסט של דף.

**ריצות test מוקפאות ב-GitHub Actions (PR 17):** ה-workflow **frozen test run** מסרב, לפני שמשהו רץ או נרשם, לאישור לא מסומן, לתג שאינו `prereg-freeze-<שם>`, לתג שלא קיים, ול-pull request של יומן גישה מריצה קודמת שעוד לא מוזג. אחרי בדיקת ה-ledger הוא עושה checkout בדיוק לתג, שם בעץ העבודה את `audit/test_access_log.jsonl` של main (המנעול מתעלם משינויים בקובץ הזה בלבד, כך שהרשומות החדשות נקשרות לרשומה האחרונה של main), ומריץ `python -m binding_gate.cli frozen-test-run`; המנעול עצמו מחליט (עץ נקי, HEAD שווה לתג, סטטוס FROZEN) ורושם את הגישה. כל המודלים של שכבה רצים ב-job אחד ובגישה אחת, כי פריט 18 בסעיף 17 עוד פתוח; job ב-GitHub מוגבל ל-6 שעות, ולכן הצעד בתשלום נעצר אחרי 330 דקות (ריצה שלא הסתיימה דורשת גישה נוספת ותיקון בסעיף 18). בסוף נבדק שיומן הגישה החדש הוא היומן של main ועוד רשומות של התג הזה בלבד, הוא נדחף ל-branch ‏`audit-log/frozen-<מספר הריצה>` ונפתח pull request ל-main; התוצאות שמותרות לפרסום נכנסות ל-`results-log`. טקסט של דפים (שכבה 3) נשאר רק ב-artifact המוצפן.

כל השלבים רצים ב-GitHub Actions:

- **dev pipeline** — שלבים 3 עד 8, שלב אחד לכל הפעלה;
- **baseline** — קונפיג אחד על ה-dev split (`cli run` או dry run) אחרי ההכנה החינמית שהוא צריך; ה-dev pipeline קורא לו;
- **frozen test run** — שלב 10;
- **results log** (אוטומטי) — הדוחות של כל ריצה ב-branch ‏`results-log`.

הפקודות שמסומנות "CLI" בשלבים הן מה שה-workflows מריצים; על מחשב (ראו "הכנה מקומית") הן נותנות אותה תוצאה, אבל אף שלב לא מחייב אותן.

### איפה לוחצים (בכל שלב workflow)

GitHub ← הריפו ← לשונית **Actions** ← בעמודה השמאלית **baseline** ← כפתור **Run workflow** מימין ← למלא את השדות בדיוק לפי הטבלה של השלב ← הכפתור הירוק **Run workflow**. "מסומן" / "לא מסומן" מתייחס לשתי תיבות הסימון. ריצה בתשלום קורית רק כש-"Dry run" לא מסומן **וגם** תיבת האישור מסומנת. השדה השישי, "Seed runs" (`seed_run_id`), נשאר ריק, חוץ מבשלב 6, שבו כותבים בו את המספר של ריצת ה-workflow של שלב 4.

תוויות המודלים: ראשיים `openai-low`, `google-low`, `zai-low`; מודלי ביניים `openai-mid`, `google-mid`, `zai-mid` (רק ב-smoke ובריצת ה-test של מודלי הביניים). ב-`configs/dev_llm_judge_checks.toml`, `configs/dev_live_smoke.toml` יש רק `openai-low`; ב-`configs/dev_live.toml` יש `openai-low` ו-`google-low`. עם `all` כל מודל רץ כ-job נפרד במקביל, חוץ מקונפיגים של web חי (שכבה 3) שרצים כ-job אחד על כל המודלים שיש להם מפתח.

התוצאות נמצאות בעמוד הריצה תחת **Artifacts**: `runs-<תווית מודל>` (manifest, traces, דוח לכל מודל) ו-`baseline-report` (תוצאת כלל העצירה לכל המודלים). בריצות web חי: `runs-encrypted-all-models` (תיקיית הריצה, מוצפנת) ו-`snapshot-manifest-all-models` (כתובות, זמנים, hash; בלי טקסט של דפים). לניתוח מקומי לפרוס כל `runs-<תווית>` לתוך `runs/`: `unzip runs-openai-low.zip -d runs/`, או `gh run download <מזהה הריצה> -n runs-openai-low -D runs/`.
